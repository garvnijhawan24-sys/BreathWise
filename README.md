# BreatheWise — Air Quality Intelligence & Forecasting

BreatheWise is a dual-source environmental intelligence web platform providing side-by-side access to:
1. **Atmospheric Model Estimates** (Open-Meteo Air Quality API)
2. **Ground Monitoring Station Observations** (OpenAQ API v3)

> **Current Phase:** Phase 5 (Environmental Reports & Deployment Preparation)  
> **Integrity Principle:** Never combine model forecasts and physical sensor readings into a single deceptive number. Always preserve station coordinates, distance, original units, provider provenance, and explicit ML status notices.


---

## Architecture Overview

- **Project Root:** `D:\BreatheWise_Docs_Only\breathewise\`
- **Frontend (`frontend/`):** React 19, TypeScript, Vite, Tailwind CSS v4, Lucide React.
  - Interactive coordinate selection with preset locations and bounded search radius (10–100 km).
  - Dedicated **Atmospheric Model Estimates** section displaying European AQI (EAQI), US AQI (USAQI), and 6 key pollutants.
  - Dedicated **Physical Ground Monitoring Stations** section displaying nearby stations, great-circle distance in kilometers, installed sensors, and recent observations.
  - Asynchronous race protection using `AbortController` on rapid location or station switching.
- **Backend (`backend/`):** Python 3.13, FastAPI, Uvicorn, Pydantic v2, HTTPX, Pytest.
  - Service clients for Open-Meteo (`services/open_meteo.py`) and OpenAQ (`services/openaq.py`).
  - Strict coordinate fidelity: preserves caller requested coordinates while exposing model grid coordinates.
  - Bounded in-memory LRU cache (`services/cache.py`):
    - Open-Meteo model data: 15-minute TTL (max 256 entries).
    - OpenAQ station discovery: 1-hour TTL (max 256 entries).
    - OpenAQ station measurements: 10-minute TTL (max 256 entries).

## API Endpoints

### 1. `GET /api/health`
Reports core service health:
```json
{
  "status": "healthy",
  "service": "breathewise-backend",
  "environment": "development",
  "version": "0.3.0",
  "features": {
    "open_meteo": "operational",
    "openaq": "operational",
    "ml_predictions": "model_not_trained",
    "database": "disabled"
  }
}
```

### 2. `GET /api/air-quality/current`
Fetches current atmospheric model estimates from Open-Meteo.
- Query parameters: `latitude` (float, required), `longitude` (float, required).
- Preserves caller coordinates while returning `grid_latitude` and `grid_longitude`.

### 3. `GET /api/stations/nearby`
Discovers physical monitoring stations indexed by OpenAQ API v3.
- Query parameters:
  - `latitude` (float, required, `-90.0` to `90.0`)
  - `longitude` (float, required, `-180.0` to `180.0`)
  - `radius_km` (int, optional, default `25`, max `100`)
  - `limit` (int, optional, default `10`, max `20`)
- Returns station IDs, names, exact station coordinates, distance in meters, locality, and sensor parameters.

### 4. `GET /api/stations/{station_id}/measurements`
Retrieves recent ground-sensor readings from OpenAQ for a specific monitoring station.
- Returns parameters, observation timestamps, sensor IDs, and physical units (e.g. `µg/m³`).

### 5. `GET /api/forecast/ml`
Retrieves the short-term PM2.5 forecast generated by the local Scikit-Learn Random Forest model.
- Query parameters:
  - `station_id` (int, optional): Ground monitoring station ID.
  - `hours` (int, optional, default `24`, range `1–72`): Forecast rollout horizon.
- Response contains:
  - `status`: `"model_not_trained"` (when no validated artifact is loaded) or `"operational"`.
  - `mae`, `rmse`: Model evaluation metrics on held-out chronological test data.
  - `baseline_mae`, `baseline_rmse`: Persistence ($t-1$) benchmark metrics.
  - `predictions`: Array of hourly forecast points with timestamps and predicted concentrations.
  - `metadata`: Comprehensive training interval, feature list, and data quality summary.

### 6. `GET /api/reports`
Generates a location-specific Environmental Intelligence Report in JSON format.
- Query parameters:
  - `latitude` (float, required, `-90.0` to `90.0`)
  - `longitude` (float, required, `-180.0` to `180.0`)
  - `radius_meters` (int, optional, default `25000`)
- Aggregates Open-Meteo atmospheric model estimates, nearby OpenAQ ground stations, and local ML status with strict provenance separation and disclaimers.

### 7. `GET /api/reports/export`
Exports the location report in structured, RFC 4180-compliant CSV format.
- Query parameters: `latitude`, `longitude`, `radius_meters`, `format=csv`.
- Preserves table sections, timestamps, metric units, provider CC BY 4.0 attributions, and scientific notices.

## Machine Learning Pipeline (Phase 4)

- **Pollutant Target:** Short-term PM2.5 concentration ($\mu\text{g/m}^3$).
- **Zero Temporal Leakage Policy:**
  - All lag features look strictly backwards: `lag_1` ($t-1$), `lag_3` ($t-3$), `lag_6` ($t-6$), `lag_24` ($t-24$).
  - Rolling windows (`rolling_mean_6`, `rolling_mean_24`) are calculated on `shift(1)` so the target at time $t$ never leaks into rolling features.
- **Hourly Regularization & Gap Tracking:**
  - Timestamps are UTC-normalized and aligned to a strict 1-hour grid.
  - Distinguishes observed zeros from missing readings. Short gaps ($\le 2$ hours) are bounded-interpolated for lag continuity; longer gaps remain NaN.
- **Mandatory Persistence Baseline:**
  - Every model evaluation benchmarks against a naive persistence predictor ($y_t = y_{t-1}$).
  - A model is not considered valid unless evaluated MAE on held-out test data outperforms the baseline.
- **Chronological Holdout:**
  - Strictly chronological 80% train / 20% test split without random shuffling.
- **Model Artifacts:**
  - Serialized via `joblib` into `backend/models/air_quality_model.joblib`.
  - Accompanied by audited JSON metadata (`air_quality_model_meta.json`).
  - Loaded only from trusted local paths.

## OpenAQ API v3 Verification & Authentication
- **Verified Endpoint:** `https://api.openaq.org/v3`
- **Authentication Policy:** OpenAQ API v3 enforces mandatory authentication via the `X-API-Key` HTTP header. Unauthenticated requests return HTTP 401:
  ```json
  {"message": "Unauthorized. A valid API key must be provided in the X-API-Key header."}
  ```
- **Configuration:**
  - Set `OPENAQ_API_KEY=your_key_here` in `backend/.env`.
  - Keys remain strictly on the backend and are never sent to the frontend or checked into Git.
  - If the key is omitted, OpenAQ endpoints return a descriptive HTTP 401 error (`OPENAQ_AUTH_REQUIRED`), while Open-Meteo forecasts and backend health check remain 100% operational.

## Local Setup & Development Commands

### 1. Backend Testing & Run
```powershell
cd backend

# Run automated tests (31 tests covering validation, mocking, ML pipeline, auth, and regression)
python -m pytest -v

# Start FastAPI server
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```
Interactive API docs: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 2. Frontend Build & Dev
```powershell
cd frontend

# Run TypeScript type check and production build
npm run build

# Start Vite development server
npm run dev
```
Frontend URL: [http://localhost:5173](http://localhost:5173)
